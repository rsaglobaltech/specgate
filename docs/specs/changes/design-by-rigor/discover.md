# Discover: design-by-rigor

> Owner: product — what the business needs and why. No technology here: the
> design says how.

## Context

A person reviewing a project found the design layer saying two things at once:
status asked for it before the tasks, while the build went ahead without it;
an empty design counted as answering the first two acceptance criteria; and an
unwritten design passed the strict check without a word.

## Use case

A team decides per change whether the design is owed: small changes without
one, large ones built only once it is written and agreed.

## Acceptance criteria

- AC-1: An empty design answers no acceptance criterion.
- AC-2: A change marked full is built only once its design is written and approved, and the team is told when it is not written.
- AC-3: A change marked lite neither asks for a design nor waits for one.
