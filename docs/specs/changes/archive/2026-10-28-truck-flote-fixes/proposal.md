# Proposal: truck-flote-fixes

## Intent

Building truck-flote, a Java and React product generated by forja, with
Specgate 0.27.1 found two defects in Specgate (S15 and S16 in that project's
`docs/specgate-issues.md`):

- `quality init` read only the root's build files. forja puts the Spring Boot
  API in `apps/api/pom.xml`, so the strict level wrote no Java check at all:
  no JaCoCo, PIT, SpotBugs or PMD.
- `init --forja` fetched `@rsaglobaltech/forja@1` with npx, a package that is
  not on npm, and npm's 404 was all the person saw.

## Scope

In scope:

- Quality presets for each application folder with its own build file, run
  in that folder, and one Semgrep scan with every stack's rules.
- forja found on the PATH first; when there is none and npm cannot give it,
  a message that says how to install it and names the override.

Out of scope:

- Publishing forja, and forja's own issues (F4–F7), which belong to forja.

## Approach

`detectApps` returns each stack with its folder; a check of a sub-folder runs
`cd <folder> && …` and names its report and SARIF from the root.
`{changed_classes@<folder>}` and `{changed_src@<folder>}` give the changed
files under that folder, relative to it. `forjaCommand` prefers a `forja` on
the PATH; before running npx, `init --forja` asks npm whether the package
exists and stops with the fix when it does not.
