# Runtime Environments

> Normative contract, generated by `specgate init`. The environments below are the
> only ones this project recognises. Code must read its configuration from the
> environment — never hardcode a host, port or credential.

## Environment catalog

| Environment | Purpose | Env file | Database |
| --- | --- | --- | --- |
| dev | Local development and day-to-day implementation | `.env.dev` | `my_spec_driven_app_dev` |
| feature | Short-lived branch or preview validation | `.env.feature` | `my_spec_driven_app_feature` |
| prod | Production-like configuration contract | `.env.prod` | `my_spec_driven_app_prod` |

Declared environments: `dev,feature,prod`
Default environment: `dev`

The active environment is selected with `APP_ENV`. An unset `APP_ENV` means
`dev`.

## Database

- Engine: `postgres` (version `16`)
- Application user: `my_spec_driven_app_app`

| Environment | Host port | URL |
| --- | --- | --- |
| dev | `5432` | `postgresql://my_spec_driven_app_app:change-me@db:5432/my_spec_driven_app_dev` |
| feature | `5433` | `postgresql://my_spec_driven_app_app:change-me@db:5432/my_spec_driven_app_feature` |
| prod | `5434` | `postgresql://my_spec_driven_app_app:change-me@db:5432/my_spec_driven_app_prod` |

Each environment binds a different host port so two of them can run side by
side. Inside the network every database listens on `5432`.

## Docker

- Compose file: `docker-compose.yml`
- Database image: `postgres:16`
- Service name: `db`

Bring one environment up:

```bash
APP_ENV=dev docker compose --env-file .env.dev up -d db
APP_ENV=feature docker compose --env-file .env.feature up -d db
APP_ENV=prod docker compose --env-file .env.prod up -d db
```

## Devcontainer

- Configuration: `.devcontainer/devcontainer.json`
- The devcontainer joins the same Compose network as the database service,
  so it reaches it at `db:5432`.

## Invariants

These hold for every environment. A change that breaks one is a defect, not a
configuration choice.

1. **No shared databases.** Each environment owns its own database name; the three above never point at the same instance.
2. **No credentials in the repository.** The generated `.env.*` files carry placeholders. Real secrets arrive from the deployment platform or a secret manager, never from a commit.
3. **No hardcoded configuration.** Hosts, ports and credentials are read from the environment at runtime.
4. **`.env.example` is the schema.** Every variable the application reads must appear there, with a safe placeholder value.
5. **Adding an environment is a spec change.** Extend this document and the `.env.*` set together — a new environment that exists only in deployment configuration is drift.
